# Indonesian, Dutch and Russian starter — inactive prototype

Historical first probe, superseded by [r02](../expansion-starter-20261117-r02/README.md).
Later review found this revision also matched noun modifiers in “coffee grounds”
and “book jacket.” Its positive examples are not evidence of safe automatic
switching. The corrected revision retains the resulting loss of coverage.

Six English-to/from candidate packs contain 18 patterns for coffee, tea and a written book. They use the existing source-frame field shapes and finite `local_phrase` contexts, but deliberately carry empty approval hashes and `source_only_permission: false`; they are not loadable as production frames. Existing Android and Apple language whitelists also reject these language codes. No client, asset, selector, approved catalog or store listing is changed here.

Dictionary evidence is the English Wiktionary translations linked per concept in `seeds.json`, CC BY-SA 4.0; page histories identify contributors. Contexts are newly authored model hypotheses, not dictionary examples or native-language QA. Russian readings use manually documented, plain-Latin adaptations of supplied Wiktionary readings; they are not generated generic pronunciation. Only the Russian noun form `книга` is admitted, never its other case forms by implicit stemming. English `book` is permitted only in explicitly listed reading contexts, not reservation use; `tea` and `coffee` are confined to drinking contexts. Whole focus edges and protected literal handling remain necessary; no casefold or automatic inflection is inferred.

`python3 build.py` regenerates six deterministic candidate files and the hash manifest. `python3 evaluate.py` checks 15 small independently authored follow-up examples against a Python approximation: six specified outputs, and nine abstentions for ambiguous words, longer words, URL/email protection, uppercase or unsupported normal messages. Examples: `I drink coffee after lunch.` -> `I drink kopi after lunch.` (English to Indonesian), `We are reading the book tonight.` -> `We are reading the boek tonight.` (English to Dutch), `I drink tea each morning.` -> `I drink чай each morning.` with reading `chay`, and `Я пью чай дома.` -> `Я пью tea дома.`. These are unactivated diagnostic simulations, not native emissions or a population accuracy/coverage estimate. Exact local phrase matching deliberately misses ordinary variants such as `I like tea.` and `Can you bring me coffee?`. The Python approximation cannot establish native tokenizer or masking parity.

Host eSpeak compiler evidence is in `speech-build-receipt.json`; the optional build-list extension leaves the production default unchanged. The expanded host data retained all 367 baseline data files byte-identically and added id/nl/ru dictionaries. Russian is about 9.08 MB, materially larger than Indonesian/Dutch. Generated assets are intentionally not committed. Android's actual native voice test on one emulator found no installed offline OS voice for Russian, Hindi, Bengali or Thai; that result is device-specific. Neither the compiled dictionaries nor a listed system voice proves audible, offline, correct native fallback synthesis.

To advance: extend source-frame and source/target reading gates in inactive native builds, add explicit reviewed eSpeak language mapping and exact generated assets, then exercise actual paired native matcher/tokenizer/mask/density behavior, Russian readings and offline synthesis on Android and Apple. Add wider vocabulary and independent ordinary-message holdouts before considering a product language option. The owner has authorized implementation and store delivery; actual qualification of the language behavior is still required before release.
