# Inactive Arabic exact-reading candidate: Android QA

The candidate was supplied privately to emulator-5620 and read with Android SQLite using exact binary surface matching. It is not registered in the app or present in the release artifacts. Hashes for the 929,775-byte compressed and 6,008,832-byte expanded files matched the candidate manifest. The tested headwords كوب, مدينة and موسيقى returned their supplied Latin readings; ضع, بالوعة, كوبx, كُوب and كتاب abstained. This is a narrow smoke test, not evidence of semantic correctness or pronunciation quality.

On this emulator, inflation took 91 ms, database open 0.42 ms, and the eight first lookups had median 0.093 ms and maximum 0.406 ms. Process PSS snapshots increased from 112,550 to 125,079 KiB, but those are noisy whole-process observations, not isolated memory attribution. Private account, preferences and messages were byte-identical. An initial setup attempt failed on an ADB shell quoting check before the candidate was copied; the corrected run is retained separately. Attribution and CC BY-SA 4.0 provenance are in the candidate's retained manifest and attribution file. Activation, independent pronunciation review and licensing/distribution integration remain open.
