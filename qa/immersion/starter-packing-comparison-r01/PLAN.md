# Same-budget starter packing comparison

This non-activated comparison uses the accepted native Japanese and Swahili starter packs, unchanged production Kotlin loaders, and the retained final 128 sources × 3 caller-exclusion snapshots per pair. The source sets differ between pairs. Their past reviews and outputs are exposed diagnostic evidence, not held-out population coverage.

The test-only provider calls each unchanged loader to obtain the actual candidate trace and complete recognition inventory. It verifies exact original entry, concept, face, record and UTF16 identity, and obtains costs from `LocalImmersion.words`. It then visits eligible candidates in the original stable priority: content before function, training rank ascending, source-token length descending, source start ascending, original insertion order for ties. Whole nonoverlapping units fit greedily within `max(1, floor(nativeWordCount × .25))`; there is no new budget, score or content. It does not maximize a different objective or prefer particular words. Known concepts remain exclusions in this experiment.

All original recognition/mask records survive, including blocked and known candidates. The wrapper uses the native `SourceReferencePresentation.create` and `SourceLookupEvidence.filterPartial`, then the unchanged `ConversationImmersion` source-provider injection seam. Final native assembly may withhold additional spans; these are reported rather than force-inserted. The test records both direct-starter and actual-route output, so existing exact-reference priority is not confused with starter gain.

Every baseline row must reproduce retained native word ranges, full candidate trace, direct selected spans, complete-route spans and mixed text. Partial output from a failure is retained but receives no comparative credit. All 768 outputs, exact additions/losses, native token costs, budget, original masks and provenance remain available. Anonymous full-source/options are physically separate from method keys; root's deterministic changed/control subset is frozen in the protocol. No new translation, inference, Apple build or production source change is part of this experiment.

## Familiarity remains separate

An explicit familiar concept must not be inserted into the existing exclusion snapshot: that would restore source text. A separate caller-provided familiarity snapshot can instead affect only the phase of an already eligible, selected, provenance-bound unit: familiar units stay target-visible, while new units continue source/target cycling and deliberate source reveal remains available. It must not bypass selection, literal/name/context guards, masks or budget. Exposure, a flip and Listen do not infer mastery.

This comparison changes selection only; it does not implement familiarity, user actions, persistence or a scheduler. A subsequent native presentation test would need exact concept references (Swift already carries them; Kotlin still needs an explicit field populated from the original entry), per-span phase state, stable geometry, source reveal, and cache/request identity bound to the familiarity snapshot. Familiar spans outside the existing density budget would be another policy, not an implication of this result. No such expansion is proposed for automatic activation here.
