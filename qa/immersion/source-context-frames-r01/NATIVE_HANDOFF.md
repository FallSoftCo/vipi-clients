# Native code review handoff

This is a test-only successor to the original protocol. No production runtime, source permissions or active packs changed. No native compilation or capture has run.

The private starter overlays expose the complete original candidate list before selection. Removing the inserted instrumentation reconstructs the committed loader bytes exactly; renamed reference copies retain the old implementation. The first 1,536 native comparisons must reproduce all selected spans, references, recognition masks and traces before candidate credit. Each additional comparison repeats baseline parity.

Both adapters use exact finite literal/slot expansions, whole native words and original UTF-16 scopes. Full-context overlap with the existing native literal matcher or an atomic/ambiguous caller mask blocks permission. The private core overlay exposes ranges from that same matcher and URL trimming without changing its predicate. Atomic/ambiguous masks remain unchanged; only head-backoff recognition intervals merge. The adapters do not derive protection solely from starter matches or from the replaced focus.

The original 154 case objects and receipt remain intact. Revision 2 adds only `@my dog is asleep.`, `#bank account is unavailable.` and `@phone charger arrived.` per pair. Focused controls additionally preserve an explicit enclosing atomic mask, verify all-known stronger-context withholding, and exercise the 128-unit ceiling. There are 160 case/pair inputs, 656 comparison rows and 780 expansion geometry checks. Density remains .25/.75, with the previously declared 0/.05 budget controls only. No slider grid is added.

Longest recognized context remains authoritative even when its output is withheld. Selection uses one native budget and cap, followed by the original starter priority. SW piano remains unchanged and earns no usefulness; Sherehe and Nambari remain exactly as retained. Exact-reference routing remains prior to the injected source lookup. All source-only permission is separately hash-bound and test-only; the seed permission fields remain false.

Android uses the retained private source tree and owned emulator 5620 only. Proposed sequence after root code approval: `python3 -B stage_android.py`, `python3 -B run_assembly.py`, then `python3 -B run_capture.py`. Stage validates the full frozen hash closure. Build uses two CPUs, one Gradle worker, existing offline dependencies, a 900-second deadline and 768 MiB additional disk reservation. Capture measures APK and DEX bytes, reserves APK + twice DEX + 384 MiB boot + 64 MiB margin + twice 32 MiB output, with an 8 GiB floor and 3 GiB available RAM. Harness body is bounded to 300 seconds; instrumentation to 600 seconds; complete owned capture to 1,200 seconds. Raw comparison output has a hard 32 MiB cap, not a claim of measured future output size. Failures remain retained and are not automatically replayed.

Apple must stage the two instrumented loaders, two renamed reference loaders, private TranslationIntegrity range overlay, FrameContextAdapter.swift, SourceContextFrameTests.swift and native-inputs-r02. Root owns staging/execution and the Mac build slot. The harness compares each platform with its own original native geometry; cross-platform differences remain evidence rather than forced equality. The enum serializer explicitly handles all four SourceAtomicMode cases.

Anonymous review options will be physically separate from method keys and seed/parallel witnesses. All unique complete outputs and additions remain reviewable. This finite development seed is not independent source-only semantic approval or population coverage.
