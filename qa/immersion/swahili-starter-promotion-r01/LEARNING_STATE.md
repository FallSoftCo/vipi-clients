# Durable learning: current seams and next decision

This is a read-only integration proposal, not an implemented learning system. The current `knownConceptIDs` seam is an **exclusion list**: it suppresses eligible units back to source text while preserving their masks. Persisting a learned set into that seam would decrease target exposure. It is not familiarity, mastery, or progressive immersion.

Current bindings:

- Apple `ConnectedChatView.swift:455` and `BotConversation.swift:182` configure language/density without known IDs. `ConversationImmersion.configure` clears pending/cache state and accepts an immutable optional exclusion snapshot. `AppState.swift` persists language, appearance, density and onboarding, not vocabulary.
- Android `ChatScreens.kt:100` and `BotConversationScreen.kt:36` construct owners without known IDs. `VipiModel.kt` persists ordinary settings in SharedPreferences. An exclusion snapshot is bound into the starter provider's cache identity; changing it requires a new owner and closing the old one.
- Apple `SourceReferencePresentation.swift:49` carries a qualified optional `conceptID`, populated by both starter loaders. Committed Kotlin `SourceReferenceUnit` carries `outputID` but **does not carry conceptID**. A future nullable field populated from the exact retained entry is the small missing data seam. No spelling-based reconstruction is needed or appropriate. Legacy/full-sentence references without a qualified concept must remain untagged.
- Both bubbles currently derive all automatic source/target phases from one `originalPhase` plus explicit per-span overrides. Both starter loaders choose at most one unit. A persistent flag alone cannot keep familiar words visible while adding new flipping vocabulary.

Keep exclusions and familiarity separate. A future explicit familiarity record should be scoped to the learner/account, source/target pair and stable catalog concept namespace; it must not imply that every occurrence or sense is correct. Only an existing, eligible, provenance-bound span may use it. Automatic flips, elapsed display time and speech playback are exposure, not proof of learning.

The smallest useful behavior to qualify next is: an explicitly familiar, already-selected span remains in the target phase; unfamiliar selected spans retain today's automatic flips; a deliberate meaning reveal remains available. This can use existing concept references and native bubble behavior without a scheduler. It changes familiarity presentation but, by itself, **does not increase coverage**, because the current one-unit selection remains.

Increasing immersion additionally requires an explicit packing decision: whether approved familiar spans remain in target text outside the *new-vocabulary* budget while one new eligible unit continues flipping. That would expose additional units that the current 25%/one-unit review never emitted. It therefore needs a frozen bounded comparison and review of all new emissions on retained inputs before activation, rather than claiming persistence safely unlocks every matching entry. Familiarity must not bypass sense/context, source masks, literal/name guards, boundaries or conflict handling.

Before implementation, resolve that budget/selection meaning and the explicit user action. Then use a small native-local versioned store with deterministic IDs, undo/reset, account/pair isolation, and defined deletion behavior; no new backend or learning scheduler. Existing account deletion does not yet erase such a store because it does not exist. Preserve the current exclusion qualification unchanged. Meaningful tests must cover relaunch persistence, account/pair separation, exact concept grouping (`families`), cache cancellation/recreation, unchanged source masks, absent IDs, explicit undo, familiar-vs-new phases, and no automatic promotion from exposure. Cross-device sync and inferred mastery remain out of scope.
