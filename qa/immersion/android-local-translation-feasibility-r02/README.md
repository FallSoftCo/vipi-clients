# Android local translation: shared synthetic feasibility probes

After the unavailable-model preflight, the user explicitly authorized preparing official ML Kit models on emulator-5620. All ten non-English models reported installed; English is built in. The device retained 648 MB free, above the 512 MiB floor. Only the two ML Kit bookkeeping preferences changed during preparation; encrypted private records, messages and all other previously snapshotted preferences matched. No message text was sent to a cloud translation service.

The shared 18-case synthetic fixture (SHA-256 `7bb7aa2bb45fda9c1ae02c20b2bf721c93eb16e90117638789568c51b64f7dc8`) then translated completely offline, with Wi-Fi and mobile data disabled and restored afterward. It records full messages, isolated selected phrases and up to two progressively expanded windows. The first call per newly created client had median 125 ms and immediate repeat median 42 ms on this emulator after model installation; these are not first-ever model cold starts or physical-device performance.

The results expose sense and scope failures: isolated verb “train” became noun “tren”; English river bank became financial “banque”; the German weather idiom was literal; Japanese omitted the acceptance; and one Swahili sentence gained incorrect negation. Literal substring occurrence incorrectly found “tren” inside “Entrengo”; complete target-word geometry rejected it, but complete matching still cannot establish meaning or alignment. The Japanese isolated output generated a Latin reading despite being semantically wrong; the Arabic isolated output had no generic native reading. Generated non-Latin output needs a verified reading and independent sense/alignment evidence before display. Neither automatic translation nor candidate 009 was activated.
