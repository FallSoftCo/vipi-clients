# Local pair speech qualification

Both local generators belong to the active conversation's language pair. Select installed voices and silently synthesize a short warm-up in each before enabling Listen. Retain both generators while the conversation is active; release them when its owner is disposed. OS voice services control actual model residency, so this is measured readiness, not a permanent residency guarantee.

The current implementation renders short messages to one PCM file. Longer messages are rendered in bounded chunks of roughly 160 characters and fed through one native audio stream: AudioTrack on Android, AVAudioEngine/AVAudioPlayerNode on iOS. Android prefetches at most two additional PCM chunks; iOS schedules at most three files. This starts playback before the whole paragraph finishes rendering and preserves the generated pauses. Chunk boundaries do not introduce extra silence deliberately. Transliteration stays on screen; synthesis receives original target-language text. Word reveals and whole-message switches invalidate pending work and stop the player. Cache identity includes every language, voice identifier and underlying text. The synthesized cache is disposable; it is not message history or a backup.

Before accepting full buffering, measure first uncached render, cache retrieval and request-to-player-start separately. Initial engineering target for an ordinary short chat message is p95 <= 500 ms after both voices are ready. This is a target, not a measured claim. Longer messages require their own latency evidence before choosing full buffering or sequential buffers on one audio stream. Do not claim player-start callbacks measure acoustic output latency.

Record leading/trailing silence and language transitions; a single file alone does not prove natural rhythm. Do not strip punctuation pauses indiscriminately or remove quiet consonants to improve a number. Listening review must assess clipping, gaps, sentence prosody, pronunciation and voice loudness. Physical-device audio route and offline tests remain necessary.

User clarification, 2026-10-24: brief silence at language switches may help comprehension. Preserve the measured pauses for listening evaluation. A 200–240 ms join is an observation, not an automatic defect or a reason to shorten it. Distinguish reliable, useful reading cadence from unpredictable engine stalls. Acceptance should favor intelligibility and comfortable immersion rather than the shortest possible silence; no zero-gap target is implied.

`qa/immersion/speech.json` is a synthetic four-word switching stress test for all 90 directions. It measures preparing both generators, alternating render, file validity and replay. It is explicitly not a linguistic or conversation-UX acceptance corpus. Each platform must additionally prove actual player completion, cancellation before rendering, cancellation while playing, reading-state invalidation, and interruption/headphone removal behavior.

## Measured experiment, 2026-10-24

All 90 directed four-word switching cases rendered on each platform. Android had no active network; Apple simulator execution does not prove offline physical-device behavior. Android p95 render was 117.8 ms; Apple p95 was 159.1 ms. These cases are rendering evidence, not 90-pair immersion UX or pronunciation acceptance.

The 441/1323/3528-character English–Spanish paragraph fixtures took 2121/471/592 ms on Android and 489/1404/4445 ms on the Apple simulator with complete buffering. Later cases repeat text, so Android's faster larger results reflect a warmed engine and must not be generalized to new messages. These results motivated bounded progressive output. Initial iOS progressive paragraph playback began at 267 ms, completed, and recorded no empty scheduling queue before completion. Android progressive-003 completed the same paragraph with zero feeding underruns and one terminal drain counter increment. Startup in that warmed run was 46.5 ms; do not treat it as uncached new-message or cold-device latency. Both platforms have actual playback/cancellation tests; listening acceptance remains open.

Keep the full-buffer experiment receipts separate from subsequent streaming results. Native player callbacks and scheduling/underrun counters do not establish acoustic latency or listening quality.

## Continuous reading integration

Listen captures the current set of familiar/target spans and pauses the automatic clock for that message until rendering/playback finishes or is cancelled. Transliteration/original-script presentation refers to the same target-language audio. Explicit word or whole-message changes invalidate pending audio; completion begins a fresh reading dwell. Native UI checks cover this state behavior separately from acoustic correctness. No reliable native word timestamps have been qualified, so synchronized word highlighting is not claimed.
